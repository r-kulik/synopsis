# Модель предметной области

Статус: проект технической модели, сохраняющий [функциональные требования](functional-requirements.md). Имена полей и границы хранения фиксируются на S01.

## Основное разделение

1. Конспект содержит знания и имеет постоянный ID.
2. Карточка представляет конспект на карте и имеет собственный ID.
3. Ребро соединяет карточки. Markdown-ссылка адресует конспект, источник или факт.
4. Контейнер лекции задаёт визуальную группировку, а не межпонятийную иерархию.

Иерархические рёбра могут образовывать циклы. Группировка контейнеров не может образовывать циклы; лекции не вкладываются друг в друга.

## Предлагаемые записи

| Запись | Основные поля | Ответственность |
| --- | --- | --- |
| Course | id, title, schemaVersion, settings | Граница базы; настройки вида |
| Note | id, courseId, kind, title, summary, markdown, revision | Источник истины для содержания; kind: lecture, concept, externalConcept, example, task |
| Card | id, courseId, noteId, position, size, lectureBoxId?, appearance? | Обычная карточка, её координаты и оформление |
| LectureBox | id, courseId, noteId, position, size | Рамка лекции; noteId указывает на Note(kind=lecture) |
| CourseRoot | id, courseId, position | Главный объект курса; название берётся из Course |
| Edge | id, courseId, kind, sourceCardId, targetCardId, label?, geometry | Явная линия карты |
| Fact | id, courseId, ownerNoteId, markdown | Комментарий одного конспекта; привязка задаётся ссылкой в markdown владельца |
| Source | id, courseId, title, assetId, pageCount? | Метаданные PDF |
| Asset | id, courseId, mediaType, relativePath, originalName, byteLength, hash? | PDF или изображение внутри базы |
| LectureSourceAttachment | lectureNoteId, sourceId, page? | Прикрепление источника к лекции без автоматического ребра |

Отдельная запись Lecture не обязательна: роль лекции можно выразить Note(kind=lecture) и LectureBox. Не хранить два независимо редактируемых названия рамки и преамбулы.

`Card.lectureBoxId` адресует именно `LectureBox.id` и означает визуальное членство карточки в рамке. Если требуется отдельно помнить лекцию определения после удаления карточки/рамки, добавить `Note.definedInLectureNoteId`, адресующее `Note.id` с kind=lecture; это техническое решение S01, а не основание дублировать конспект. Пересоздание карточки не меняет ID Note.

## Матрица рёбер

| kind | Допустимые участники | Смысл | Ограничения |
| --- | --- | --- | --- |
| contextual | concept ↔ concept | Контекстное пояснение | Подпись, ручная траектория; между разными лекциями разрешено |
| hierarchical | concept → concept | Родовое/частное отношение | Несколько родителей и циклы допустимы |
| mention | concept ↔ externalConcept | Упоминание внешнего материала | Внешнее понятие не становится участником hierarchy |
| exampleAttachment | example ↔ concept | Пример к понятию | Несколько разных понятий |
| taskAttachment | task ↔ concept | Задача к понятию | Несколько разных понятий |

Стрелки в этой таблице описывают участников. Для hierarchy предлагаем хранить направление «общее → частное». Для остальных типов семантика стрелок, возможность обратного направления, петель на саму карточку и нескольких рёбер одной пары требуют фиксации в S01 (D-08). Несколько родителей не означают несколько визуальных родителей контейнера.

Корень курса, рамки лекций, источники и факты не являются обычными понятиями. Не разрешать их участие в смысловых рёбрах по умолчанию. Структурное отношение Course → LectureBox уже задаётся принадлежностью курсу; дополнительные видимые линии от корня — открытая UX-деталь.

## Инварианты

- Все участники операции принадлежат одному курсу. Проверяется в прикладном слое, а не только в UI.
- Валидный Card.noteId и LectureBox.noteId адресуют существующий Note совместимого типа.
- Note не требует наличия Card. Удаление Card не удаляет Note.
- Предложение для v1: не более одной карточки/рамки на конспект. Повторное «Показать на карте» фокусирует существующую карточку.
- Edge требует существующие совместимые карточки; невалидные импортированные рёбра не участвуют в отображении.
- Markdown может содержать невалидную ссылку: это состояние содержимого, а не недопустимое состояние всей базы.
- Fact принадлежит ровно одному Note. Чужой Note не может использовать этот факт как общий комментарий.
- Несколько ссылок на один Fact внутри его владельца не превращают его в общекурсовую сущность. Ограничение числа таких ссылок — решение S01.
- Привязка факта определяется внутренней ссылкой в Markdown. Отдельный постоянно синхронизируемый диапазон символов не является источником истины.
- Геометрия ребра хранится данными, а не только временным SVG-путём рендера. Сохраняются контрольные точки и выбранный способ построения пути.
- Фильтр видимости не удаляет сущности и не переписывает ссылки. Предложение: ребро скрывается, если скрыт любой его конец.
- Имя файла, заголовок и текст ссылки не используются как первичный ключ.

## Операции удаления

| Операция | Удаляется | Сохраняется |
| --- | --- | --- |
| RemoveCard | Карточка и её инцидентные рёбра | Note, его Fact, ссылки на Note, вложения |
| RestoreCard | Ничего; создаётся новое представление | ID и содержимое Note; старые рёбра не восстанавливаются автоматически |
| RemoveLectureBox | Только рамка | Преамбула, дочерние карточки и их рёбра; карточки становятся свободными |
| DeleteLectureNote | Преамбула лекции и её рамка | Другие Note/Card и их связи; вложения, используемые другими конспектами |
| DeleteNote | Сам Note, его представление, инцидентные рёбра и принадлежащие ему факты | Markdown других Note с теперь невалидными ссылками; другие конспекты |

При снятии рамки сохранить мировые координаты дочерних карточек и очистить их `lectureBoxId`. Семантическая ссылка `definedInLectureNoteId`, если она хранится, сохраняется, пока существует конспект лекции. При удалении самого Note лекции очищается также эта семантическая ссылка. Ни одна принадлежность не заменяется другой лекцией случайным образом. Судьба принадлежащих удаляемому Note фактов — техническое правило удаления подчинённых данных; это не удаление других конспектов.

Источник или изображение нельзя автоматически удалять вместе с карточкой. Удаление общих вложений и сборка неиспользуемых файлов требуют отдельной политики; не вводить фоновую очистку в v1 без проверок использования.

## Прикладные команды

Предлагаемые операции общего API: CreateCourse, CreateNote, SaveMarkdown(expectedRevision), CreateCard, RemoveCard, CreateLectureBox, RemoveLectureBox, DeleteNote, CreateEdge, UpdateEdgeGeometry, SetTypeVisibility, SetTypeStyle, AttachSource, CreateFact, InsertInternalLink, ExportCourse, ImportCourse.

CreateNoteFromSelection должен сохранить Note, Card и изменённый Markdown как согласованную операцию. Изменение исходного Markdown проверяет revision, чтобы старое выделение не перезаписало новый текст. Интерфейс хранения может быть локальным HTTP API или вызовами слоя сервиса; формат команд не должен зависеть от React Flow или конкретного редактора.
