# Архитектура и повторное использование библиотек

Ниже сохранён исходный обзор кандидатов до реализации. Текущий стек зафиксирован
в [ADR-001](adr/001-s00-technical-baseline.md) и [ADR-003](adr/003-browser-ui-recovery.md):
Python 3.11+ без внешних runtime-зависимостей, отдельные HTML/JS/CSS и включённые
в поставку библиотеки UI. Запуск — `python start.py` или `Start Synopsis.cmd`,
браузер открывается автоматически. Актуальная инструкция — в [README](../README.md).
Лицензия самого репозитория — MIT.

## Предлагаемая архитектура

- Браузерный UI: карта, Markdown-редактор, отформатированное чтение, вкладки, список конспектов и настройки.
- Прикладной слой: команды курса, проверка типов, управление ссылками и согласованными операциями.
- Локальный сервер: запуск на loopback-интерфейсе, API и выдача локальных вложений по ID.
- Хранилище: метаданные/Markdown и байты вложений; независимый адаптер экспорта/импорта `.synopsis`.

Предлагаемый базовый вариант — TypeScript/React в UI; язык сервера и способ хранения выбрать на S00. Рассмотреть единый TypeScript-процесс сервера и SQLite + каталог assets как простой кандидат. Не вводить графовую БД, микросервисы, облако или аккаунты только из-за наличия графа в интерфейсе.

Исходный Markdown является каноническим. Не хранить одновременно HTML и JSON редактора как независимые редактируемые источники истины. Данные домена не должны совпадать напрямую с внутренним форматом выбранной библиотеки карты.

## Библиотеки-кандидаты

Проверено по первичным источникам 2026-09-13. Версии и лицензии конкретных устанавливаемых пакетов повторно фиксируются в lockfile и отчёте S00. Таблица не является разрешением на покупку платных компонентов.

| Задача | Кандидат | Что готово | Что остаётся Synopsis |
| --- | --- | --- | --- |
| Исходный Markdown | CodeMirror 6, MIT | Текстовый редактор и Markdown language package | Режимы read/edit, сохранение, команды вставки и связь с конспектом. [Проект](https://codemirror.net/), [Markdown package](https://github.com/codemirror/lang-markdown) |
| Markdown → чтение | remark + rehype, MIT | AST-пайплайн и позиции исходных узлов | Точная привязка DOM selection к исходнику, внутренние ссылки и локальные правки. [remark](https://github.com/remarkjs/remark), [rehype](https://github.com/rehypejs/rehype), [unist position](https://github.com/syntax-tree/unist#position) |
| Альтернатива рендера | markdown-it, MIT | Расширяемый Markdown-рендерер | Точное сопоставление выделения исходнику не дано из коробки; `Token.map` в проверенном исходнике — диапазон строк. [Проект](https://github.com/markdown-it/markdown-it), [Token версии 14.1.0](https://github.com/markdown-it/markdown-it/blob/14.1.0/lib/token.mjs) |
| Формулы | KaTeX, MIT | Отображение математического TeX | Локальные шрифты/CSS, обработка ошибок, согласованный набор команд. [Проект](https://github.com/KaTeX/KaTeX), [функции](https://katex.org/docs/supported.html) |
| Карта | React Flow, MIT | Узлы, группы, перемещение, масштаб, SVG-рёбра | Семантика объектов, контрольные точки, операции удаления, сохранение. [Проект](https://reactflow.dev/), [контейнеры](https://reactflow.dev/learn/layouting/sub-flows), [custom edges](https://reactflow.dev/learn/customization/custom-edges) |
| Готовые редактируемые линии | React Flow Editable Edge | Пример с контрольными точками | Пример имеет отдельную xyflow Pro License; не смешивать её с MIT основного пакета. [Условия примера](https://reactflow.dev/examples/edges/editable-edge) |
| Упаковка файла | fflate, MIT | ZIP, асинхронные/потоковые API | Manifest, версии, ограничения, целостность и атомарный импорт. [Проект](https://github.com/101arrowz/fflate) |

Инженерная рекомендация: сначала сравнить remark/rehype и markdown-it на задаче выделения, а не выбирать рендерер по простоте демонстрации Markdown. Возможность получить AST offset ещё не гарантирует корректное сопоставление экранированного или форматированного текста DOM.

Tiptap/WYSIWYG, MathLive и встроенный PDF.js-viewer не нужны при согласованном сценарии raw Markdown, LaTeX-кода и внешнего открытия PDF. Не включать их по инерции из раннего обсуждения.

## Границы модулей для параллельной разработки

Предлагаемые области владения; точные пути фиксирует интегратор S01:

| Область | Контракт |
| --- | --- |
| domain | Типы, команды, ошибки, инварианты курса; не зависит от UI |
| storage / server | Локальное сохранение, транзакции, assets API |
| editor | Исходный текст и режим чтения; callbacks сохранения и навигации |
| markdown | Парсинг ссылок, рендер, сопоставление диапазонов, точечные правки |
| map | Представления объектов/рёбер, геометрия, фильтры и оформление |
| library / shell | Список курсов/конспектов, вкладки, адаптивные панели |
| transfer | Формат `.synopsis`, экспорт, импорт и диагностика |

Общие типы, package manifest, lockfile, глобальная маршрутизация и миграции имеют одного владельца-интегратора. Исполнители сообщают запрос на изменение контракта до правки чужой области.

## Технические качества и проверки

- Базовый пользовательский сценарий не требует внешнего API. Предложение: паковать зависимости, шрифты и стили локально и проверять работу без сети после установки.
- Выдавать вложения через контролируемый ID текущего курса. Не принимать произвольный путь из внутреннего URL.
- HTML/URL из вставленного Markdown не должны исполнять активный код в контексте локального приложения.
- Локальные изменения и импорт должны выдерживать ошибку записи без потери последней сохранённой версии.
- Карта может отсекать отрисовку объектов за пределами viewport для производительности; это не сворачивание и не изменение логической видимости полного графа.
- Определить целевые ОС/браузеры и размер контрольного курса на S00. Не заявлять численные гарантии без измерений на указанной конфигурации.
- Локальный сервер по умолчанию не публикует приложение в LAN; это соответствует запросу `localhost`.

## Что должен доказать S00

1. Выделение в отформатированном тексте можно точно превратить в локальную правку Markdown для зафиксированного набора случаев.
2. Пользователь редактирует изгибы и подписи; геометрия переживает перемещение контейнера и повторное открытие.
3. Снимок курса переносит байты вложений и конспекты без карточек в чистое хранилище.
4. Сырой Markdown, а не формат rich-text редактора, остаётся источником истины.
