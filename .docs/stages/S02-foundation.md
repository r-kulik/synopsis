# S02 — локальная основа приложения

Статус: не начат. Входной gate: S01. Владелец: агент основы; интегратор контролирует общий запуск и зависимости.

## Комментарий пользователю

> Соберу запускаемое приложение на localhost: список курсов, локальное сохранение и рабочее пространство с картой и вкладками. Проверю, что данные переживают перезапуск.

## Scope и владение

Локальный сервер, storage adapter, базовая оболочка, каталог курсов и конспектов, assets API, команды создания конспектов/карточек на уровне сервиса. Настоящий редактор и диаграммное поведение принадлежат S03/S04.

Входы: [архитектура](../architecture.md), [UX](../ux-flows.md), [модель](../domain-model.md), контракты/ADR S01.

## Шаги

1. Настроить воспроизводимый локальный запуск по выбранному стеку, сборку и базовые проверки.
2. Реализовать хранилище курсов, конспектов, метаданных карты и файлов с атомарными операциями принятого контракта.
3. Создать главную со списком курсов, создание/открытие курса и каталог конспектов с поиском и фильтром без карточки.
4. Реализовать оболочку двух изменяемых областей и управление вкладками без привязки к внутренностям редактора.
5. Реализовать импорт локального asset по ID и безопасную выдачу в контексте курса; PDF-панель не создавать.
6. Подключить команды CRUD и общие события для будущих editor/map/transfer-модулей.
7. Проверить повторный запуск и ошибку записи; документировать расположение данных и запуск.

## Gate

- AC-01, AC-02, AC-03 (данные), AC-04 (CRUD), AC-14 (оболочка), AC-24 (каталог), AC-27 (сохранение основы).
- После перезапуска созданные конспекты не пропадают; ошибка записи не выдаётся за успех.
- Нет cloud/API-зависимости в основном сценарии; сервер запускается на localhost.
- S03/S04/S06 получают реальные адаптеры и fixtures, а не неописанные заглушки.

Проверки: чистый локальный запуск, перезапуск с сохранённым курсом, доменные и storage integration checks. Выход: основа приложения и отчёт S02. [Промпт](../prompts/S02-foundation.md).
