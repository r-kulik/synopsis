# S03 — Markdown-редактор и чтение

Статус: не начат. Входной gate: S02 и результаты Markdown spike S00. Владелец: агент редактора. Может работать параллельно S04 и S06.

## Комментарий пользователю

> Реализую работу с исходным Markdown и отформатированное чтение после сохранения: формулы, картинки и вкладки. Проверю, что вставленный текст сохраняется без нежелательного изменения разметки.

## Scope и владение

Editor/render/markdown и тесты синтаксиса. Shell подключается через контракт S02; общие команды и формат архива не меняются самостоятельно. Выделение с созданием сущностей и Fact UI — следующий этап S05.

Входы: [Markdown](../markdown-contract.md), [UX](../ux-flows.md), [приёмка](../acceptance.md), D-02/D-03/D-05/D-13 и ADR S00.

## Шаги

1. Подключить выбранный редактор исходного текста и отдельный рендер чтения.
2. Реализовать edit/save/read, обработку ошибок и согласованную политику черновиков вкладок.
3. Поддержать согласованный профиль Markdown и математический набор; хранить шрифты/стили локально по ADR.
4. Добавить локальные изображения через asset ID; определить действия с удалёнными URL и локальными путями без молчаливых потерь при переносе.
5. Отображать внутренние адреса через общий resolver; невалидные ссылки оставлять читаемыми.
6. Подготовить source-map/render API для S05, сохраняя результаты spike.
7. Проверить визуальное чтение матриц, формул, таблиц, длинного текста, изображений и ошибок.

## Gate

- AC-14–16, AC-27 для конспекта; базовая часть AC-25/26 для рендера ссылок.
- Read→edit возвращает исходный Markdown без пересериализации; сохранение не создаёт сущности из вставленного текста.
- Не появляется WYSIWYG-режим, MathLive или встроенный PDF.
- Несохранённый текст не пропадает при переключении вкладки; ошибки рендера локальны.
- Поддерживаемый синтаксис и ограничения документированы; API для S05 стабилен.

Проверки: fixtures, round trip, браузерное редактирование и визуальная проверка. Выход: editor-модуль и отчёт S03. [Промпт](../prompts/S03-editor.md).
