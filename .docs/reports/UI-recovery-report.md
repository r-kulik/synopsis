# UI recovery — рабочее браузерное приложение

> После этого прогона пользователь сообщил о 404 `/static/course.js` в своём
> экземпляре. Его дефект не закрыт результатами изолированных тестов ниже;
> факты и новая проверка доставки — [UI-delivery-incident.md](UI-delivery-incident.md).

Дата: 2026-09-13. Основание: пользовательский дефект пустого экрана с
`Unexpected token ')'` и требование красивого UI в отдельных HTML/JS/CSS.

## Результат

Заменён прежний shell с JavaScript внутри Python-строки. Реальные страницы
библиотеки и курса находятся в `frontend/index.html` и `frontend/course.html`.
Оформление — `styles.css`, поведение — отдельные читаемые ES-модули.
Пустая библиотека содержит видимое действие «Новый курс»; ошибки загрузки
показываются пользователю с возможностью повторной попытки.

UI-исполнитель `/root/ui_rebuild` разработал страницы, стили и контроллеры.
Интегратор связал их с сервером, собрал remark/GFM/math + KaTeX + CodeMirror 6,
исправил команды хранения и выполнил реальные браузерные сценарии. Субагент
не был принят только по сообщению о завершении или синтаксической проверке.

Проверенная основная цепочка: создать курс → создать лекцию и конспекты →
редактировать и читать Markdown/формулы → создать ссылки/факт/PDF → работать
с картой → экспортировать → импортировать в пустое хранилище.

## Что исправлено при интеграции и проверке

- Поля диалогов получили явные доступные имена. Кнопки меню больше не
  отправляют окружающую форму как submit.
- Устранены неверный шаг поля толщины линии, ложные focus-обводки и конфликт
  ID подсказки формы. Уведомления ограничены тремя одновременно.
- Создание лекции с текстом/описанием и создание понятия из выделения с
  принадлежностью лекции выполняются атомарно.
- Карточки получают свободные позиции; существующие объекты не перераскладываются.
  Стрелки линий видны у границ карточек, перенос рамки сохраняет координаты детей.
- Черновики отделены от серверного snapshot. Ошибки записи, переключение
  вкладок, перезагрузка и ввод во время запроса не теряют текст.
- Конфликт revision имеет диалог сравнения и явный выбор версии. Отсутствует
  автоматическая перезапись сохранённой версии локальным черновиком.
- Удаление лекции очищает структурные ссылки, но сохраняет дочерние конспекты.
- HTTP ограничен loopback Host/Origin; вложения и static разрешаются только
  внутри своих каталогов. В архиве проверяется asset.relative_path до записи,
  типы сущностей и конечность геометрии. HTML/опасные URL в Markdown не исполняются.
- Готовый bundle, KaTeX CSS/шрифты и лицензии всех включённых зависимостей
  поставляются локально. Python больше не содержит браузерную программу.

## Фактически выполненные проверки

Среда: Windows, CPython 3.14.0, Node.js 22.23.2, Playwright 1.56.1.
Браузеры: Chrome 152.0.7977.83, Microsoft Edge 153.0.4234.32, headless,
новые профили, отдельные data-dir и случайные localhost-порты.
Пользовательская `.synopsis-data` и прежнее S08-хранилище не использовались
для тестовых записей.

В текущем окружении команды Node выполнялись переносным бинарником из
`.tools/node-v22.23.2-win-x64/`; Python запускается из PATH. Код, сценарии и
зависимости те же, что используются указанными npm scripts. Автоматические
браузеры запускаются как отдельные тестовые процессы, не в пользовательском профиле.

Проверены не только видимость контролов, но и сохранённые данные после действий:

- создание всех пяти типов Note, лекция с текстом и назначенный ей concept;
- таблица, матрица, inline math, ошибка формулы, безопасный HTML/URL;
- CodeMirror, черновик между вкладками, принудительный HTTP 500 и повторное сохранение;
- поздний ввод во время отправки, восстановление после reload, оба решения конфликта revision;
- точный второй одинаковый фрагмент после emoji, escapes, emphasis и отказ внутри готовой ссылки;
- Note+Card+link из выделения без автоматически созданного Edge, раскрытие факта;
- загрузка настоящего PDF, attachment к лекции, отдельная вкладка с `#page=1`;
- загрузка PNG и реально декодированное изображение в режиме чтения;
- поиск, cardless-фильтр, ручное ребро, добавление/перемещение контрольной точки;
- перенос рамки с одинаковой дельтой её карточек, сохранение видимости типов;
- снятие/возврат карточки без удаления Note, reload с восстановлением вкладки;
- скачивание архива через UI, повторный импорт отдельной копией;
- импорт в другую пустую библиотеку: внутренние ID, текст, факты, геометрия,
  metadata вложений совпадают; меняется только ID курса и course_id сущностей;
- видимая ошибка при намеренно недоступном JS-модуле, узкие раскладки без
  горизонтального переполнения, клавиатурное изменение ширины панелей.

## Границы результата

Это восстановление рабочего UI, **не повторная независимая приёмка всех
AC-01–31 S08**. Старый release gate не изменён задним числом. В частности:

- Не измерены бюджеты большого курса; полный performance baseline остаётся открытым.
- Не выполнены полный accessibility-аудит, touch/mobile suite, Safari/Firefox QA.
- Выделение ограничено одним безопасным текстовым AST-фрагментом; межблочные
  диапазоны, код, формулы, HTML, task-list и готовые ссылки не патчатся.
- PDF использует просмотрщик браузера. Проверена вкладка и адрес страницы,
  а не фактический визуальный номер в интерфейсе PDF-viewer для всех файлов.
- В основном сценарии нет обращений к CDN/внешним ресурсам; физическое
  отключение сетевого адаптера отдельно не выполнялось.
- Нет совместной работы или блокировки между двумя серверными процессами;
  один data-dir должен обслуживать один процесс.
- Внешние изображения не скачиваются автоматически, а требуют локального импорта.

## Передача пользователю

Остановить старый сервер Ctrl+C, запустить его прежней командой с прежним
data-dir и обновить страницу Ctrl+F5. Изменённый Python-код не подменяется в
памяти уже запущенного процесса. Полная актуальная инструкция —
[QA-USER-GUIDE.md](../QA-USER-GUIDE.md); структура UI —
[UI-FRONTEND.md](../UI-FRONTEND.md), решения — [ADR-003](../adr/003-browser-ui-recovery.md).
