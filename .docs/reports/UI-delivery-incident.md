# UI delivery — обращение о 404 course.js

Дата: 2026-09-14. Статус пользовательского дефекта: **не закрыт до проверки
того экземпляра, который обслуживал localhost:8765**.

Пользователь сообщил, что библиотека и создание курса работают, но конспект
не создаётся, а `/static/course.js` возвращает JSON «Файл интерфейса не найден».
Это объясняет отсутствие обработчиков рабочей зоны; причина, по которой
конкретный процесс не нашёл файл, не установлена.

## Факты

- В рабочей копии `C:\Users\Bulkin\synopsis\frontend\course.js` существует,
  непустой и читается текущим Python-процессом.
- На момент диагностики запросы к localhost:8765 и 127.0.0.1:8765 получили
  connection refused, в том числе повторный read-only запрос вне песочницы.
  Пользовательский экземпляр и его пути не удалось осмотреть. Другой сервер
  на его порту вместо него не запускался, рабочее хранилище не изменялось.
- Предыдущие браузерные сценарии проверяли отдельные тестовые процессы и
  хранилища. Их успех не доказывал доставку файлов именно с пользовательского порта.

## Внесённые изменения

- `server/frontend_assets.py`: проверка HTML, JS, CSS, favicon и всех KaTeX-шрифтов
  до запуска. Неполный комплект не создаёт даже каталог данных.
- `GET /api/health`: instance/process ID, абсолютные пути UI и data-dir,
  перечень отсутствующих файлов, контрольные суммы текущего комплекта.
  В ответах есть `X-Synopsis-Instance`, в терминале — строка `UI: ...`.
- Ошибка статического маршрута указывает запрошенный файл и адрес диагностики.
- Кнопки создания конспекта включаются после успешной загрузки программы и курса.
  При 404 модуля независимый guard показывает его URL и диагностику процесса.
- `npm run check:running -- --url http://localhost:8765`: read-only проверка
  файлов и формы конспекта в уже запущенном экземпляре. POST заблокирован
  проверяющим браузером. Полное создание остаётся отдельным изолированным E2E.
- В регрессии добавлены точный localhost URL, SHA-256/MIME всех 71 файлов,
  отказ запуска без course.js и браузерная подмена ответа course.js на HTTP 404.

## Проверки

`python -m unittest -v tests/test_ui_delivery.py`: 3/3 успешно.
`node tests/ui/browser-flow.mjs`: доставка 71 файла, открытие формы и полный
сценарий создания/переноса успешно в тестовом Chrome 152.0.7977.83.
`node --test tests/ui/*.test.mjs`: 2/2, включая точный случай HTTP 404 для
course.js, видимую ошибку и отключённую кнопку создания.
Полный Python-прогон с новыми тестами: 45/45 успешно.
Повторный `check:running` против localhost:8765 завершился ECONNREFUSED как
для ::1, так и для 127.0.0.1 — это не успешная проверка пользовательского экземпляра.

Для завершения диагностики требуется запущенный пользовательский экземпляр
или его точная команда, папка запуска и первые строки вывода. Восстановление
конкретного пользовательского сценария не объявляется по успеху этих тестов.
