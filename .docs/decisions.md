# Решения и открытые вопросы

Этот реестр предотвращает повторное обсуждение уже принятых правил и выдачу технических предложений за пожелания пользователя.

## Отменённые/неприменимые предложения

- Разделы/модули: обсуждались и сначала были приняты, затем явно исключены пользователем. Не возвращать их в схему и UI.
- Сущность «Вопрос», совместная работа, AI-генерация и автоматический анализ источников — вне объёма.
- Внешнее понятие из глобальной библиотеки — противоречит изоляции курсов.
- Сворачивание лекций или ветвей — противоречит полному отображению карты.
- WYSIWYG/Notion-подобное редактирование, визуальная математическая клавиатура и PDF-панель — не нужны после уточнений.
- Автоматическое ребро из каждой Markdown-ссылки — прямо запрещено.
- Запрет циклов в межпонятийной иерархии — не соответствует требованиям.
- Удаление карточки вместе с конспектом и каскадное удаление содержания лекции — запрещены.

## Открытые решения и предлагаемые baseline

| ID | Вопрос | Предложение / способ решения | Когда и кто |
| --- | --- | --- | --- |
| D-01 | Стек, локальное хранилище, запуск, ОС/браузеры | Выбрать по прототипам; зафиксировать команды установки, версии и проверенную платформу | S00, интегратор; запрос пользователю только при существенном платформенном ограничении |
| D-02 | Точный Markdown/LaTeX профиль | CommonMark + перечисленные GFM-возможности и математические fixtures; ограничения сделать явными | S00, редактор + интегратор |
| D-03 | Сложные выделения, существующие ссылки, несколько абзацев, факт поверх ссылки | Прототип; никогда не портить исходник. Возможные ограничения продемонстрировать как продуктовый компромисс, а не молча урезать требование | S00, редактор; пользователь при необходимом существенном ограничении |
| D-04 | Повторный импорт курса | Предпочтительно импортировать независимую копию с новым courseId; не перезаписывать без явного выбора | S01, интегратор |
| D-05 | Черновики и экспорт | Явное сохранение Markdown; черновик вкладки сохраняется при переключении; экспорт согласованной сохранённой версии с видимым состоянием | S01, интегратор; S03 реализует |
| D-06 | Группировка внешних понятий, задач и примеров; место новых карточек | Свободные карточки разрешены; назначение лекции явное; обычное понятие связывается с лекцией определения | S01/S04, интегратор; не выбирать за пользователя обязательное размещение всех вспомогательных объектов |
| D-07 | Несколько карточек одного Note | Baseline 0..1; повторное «Показать на карте» фокусирует существующую | S01, интегратор |
| D-08 | Направление рёбер, self-loop и параллельные рёбра | Hierarchy хранит «общее → частное»; циклы из нескольких понятий разрешены. Остальное описать явно до карты | S01, интегратор |
| D-09 | Источники на карте, корень → лекция, конспект курса | Не вводить новые карточки/линии по умолчанию; корень курса обязателен, PDF доступен через список источников и прикрепления | S01/S04; существенное расширение уточнить у пользователя |
| D-10 | Состав настроек и правила геометрии | Цвет/форма/обводка карточки; цвет/толщина/штриховка/стрелка/подпись линии; типовые настройки курса. Контрольные точки при перемещении концов проверить в spike | S00/S04, карта + интегратор |
| D-11 | Размеры базы и скорость работы | Измеряемый набор fixtures и целевая конфигурация; сначала baseline, затем целевые бюджеты | S00, уточнение S08 |
| D-12 | Количество PDF у лекции и замена файла | Модель допускает прикрепления; UI минимум один необязательный источник. Замена PDF не должна молча менять смысл номеров страниц | S01/S05, интегратор |
| D-13 | Markdown с удалёнными картинками и локальными путями | Локальные вложения переносятся всегда; внешние зависимости диагностируются, явное добавление в курс перед самодостаточным экспортом | S03/S06, интегратор |
| D-14 | Полноценный offline после установки | Рекомендуется локальная упаковка ресурсов без CDN. Это технический baseline; пользователь явно потребовал localhost, не конкретный установщик | S00/S08, интегратор |
| D-15 | Техническая принадлежность детей и восстановление рамки | Сохранение преамбулы уже принято (A-18); определить поля визуальной/семантической принадлежности и правила новой рамки | S01, интегратор; соблюдать FR-070–076 |

Наличие D-ID не означает, что вся разработка остановлена. Решение принимается перед зависящим от него этапом. Рутинный технический выбор выполняет интегратор; изменение продукта или обещаний пользователю выносится на обсуждение.

## Формат записи решения (ADR)

Создать `.docs/adr/NNN-name.md` по мере появления решения: контекст; связанный D-ID; рассмотренные варианты; выбранное решение; доказательства прототипа/ссылки; последствия; ограничения; затронутые документы; дата. Сейчас ADR не созданы, потому что технические проверки ещё не выполнены.
