# Шаблон отчёта этапа

Скопировать в `.docs/reports/Sxx-report.md` после выполнения работы; заменить поля фактами. Этот файл — шаблон, а не отчёт о выполненном этапе.

## Состояние

- Этап:
- Исполнитель и интегратор:
- Статус: не начат / в работе / готов к проверке / принят / есть блокирующие замечания.
- База проверки: commit или описание состояния рабочей директории.

## Результат

Что изменилось для пользователя или следующего исполнителя. Перечень основных файлов/модулей и новых публичных контрактов.

## Прослеживаемость

| FR / AC | Статус | Доказательство или воспроизведение |
| --- | --- | --- |
| Указать ID | Выполнено / не выполнено / не применимо с причиной | Тест, команда, скриншот или ручные шаги |

## Проверки

Реальные команды, окружение и результаты. Отдельно указать проверки, которые не запускались, и причину. Для визуальных сценариев — что именно осмотрено. Для отказов — какой сбой воспроизведён и сохранились ли данные.

## Решения и ограничения

Принятые ADR/D-ID, ограничения библиотек, незакрытые вопросы, что изменилось относительно входного контракта. Не скрывать заглушки или непроверенные ветви.

## Передача следующему этапу

Доступные API/fixtures, команды запуска, необходимые данные, ожидаемые зависимости и границы владения.

## Проверка интегратором

Дата, проверенные сценарии, замечания, итог gate. Этот раздел заполняет интегратор после фактической проверки.
