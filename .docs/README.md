# Synopsis — документация продукта и разработки

Текущий запуск и описание проекта — в [README](../README.md), пользовательские
сценарии — в [руководстве](QA-USER-GUIDE.md). Приложение реализовано с локальным
Python-сервером и отдельными HTML/JS/CSS; текущие проверки и ограничения —
в [отчёте UI](reports/UI-recovery-report.md). Полная независимая приёмка S08
не закрыта. Документы требований и план ниже сохраняют исходную редакцию 2026-09-13.

Synopsis — локальное браузерное приложение для студента: редактируемые Markdown-конспекты и вручную организуемая карта знаний внутри полностью изолированного курса.

## Как читать статус утверждений

- **Требование** — решение, принятое в обсуждении; менять его техническим удобством нельзя.
- **Предложение** — рекомендуемая реализация или UX-деталь; её можно заменить с объяснением и сохранением требований.
- **Открыто** — существенная продуктовая неопределённость; условия решения перечислены в [реестре](decisions.md).

При расхождении документов приоритет имеют последние явные решения пользователя, затем функциональные требования, затем модель и контракты, затем план и промпты. Найденное расхождение нужно исправить в документах, а не обходить в коде.

## Порядок начала работ

1. Прочитать функциональные требования и решения.
2. Выполнить S00: проверить наиболее рискованные взаимодействия и записать технические решения.
3. Зафиксировать контракты в S01; после этого запускать этапы по зависимостям.
4. Завершать каждый этап проверкой и отчётом. Наличие кода или успешная сборка сами по себе не означают приёмку.

В этом пакете нет обещания поддержки произвольного LaTeX, любых расширений Markdown или любой производительности карты. Проверяемый набор синтаксиса и измеримые бюджеты должны быть зафиксированы на S00/S01. Базовые пользовательские требования при этом остаются обязательными.
