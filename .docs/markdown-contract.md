# Контракт Markdown, ссылок и выделения

Статус: предлагаемый контракт v1; результаты прототипа S00 уточняют реализацию, сохраняя FR-040–051. Исходный Markdown — канонический текст конспекта. HTML чтения является производным представлением.

## Профиль синтаксиса

Baseline для проверки: CommonMark + GFM-таблицы, зачёркивание и task lists; заголовки, абзацы, вложенные списки, цитаты, emphasis/strong, обычные ссылки, изображения, горизонтальные линии, inline code и fenced code blocks. Дополнение: `$...$` и `$$...$$` для формул.

Это операционное уточнение требования «Markdown и LaTeX», а не обещание всех диалектов. Сноски, raw HTML, диаграммы в кодовых блоках, вложенные HTML-компоненты и дополнительные математические макросы не считаются автоматически включёнными. Поддержку и безопасное отображение raw HTML определить на S00; предпочтение — не исполнять HTML/скрипты из конспекта.

Проверочный математический набор: индексы и степени, дроби, корни, греческие буквы, векторы, матрицы `matrix/pmatrix/bmatrix`, определители, системы `cases`, выравнивание `aligned`, суммы, произведения, стандартные операторы и текст внутри формул. Неподдержанная команда оставляет исходник доступным и даёт локальную диагностику.

Исходный текст сохраняется без пересериализации всего документа. Сохранение не должно нормализовать вручную пробелы, разделители emphasis или ссылки только потому, что рендерер предпочитает иной стиль.

## Внутренние адреса

```markdown
[Матрица](synopsis://note/note-42)
[Презентация](synopsis://source/source-8)
[Слайд 12](synopsis://source/source-8?page=12)
[поясняемый фрагмент](synopsis://fact/fact-3)
![Геометрический смысл](synopsis://asset/asset-9)
```

Схема `synopsis://` — внутренний формат приложения, а не внешний стандарт. В обработчике URL ресурсный тип (`note`, `source`, `fact`, `asset`) находится в authority/host, ID — в path. Использовать единый парсер и генератор адресов, не дублировать разбор regex в компонентах.

- ID стабильный и не зависит от названия.
- Курс определяется текущей открытой базой; внутренний адрес не переходит в другой курс.
- `page` — целое положительное число, нумерация с 1. Если число страниц известно, дополнительно проверяется верхняя граница.
- `fact` открывается только в Note, которому принадлежит Fact.ownerNoteId.
- `asset` используется как адрес вложения изображения; реальные дисковые пути не попадают в Markdown.
- При неизвестном ID отображается невалидная ссылка с сохранением пользовательской подписи.
- Пользователь может вручную вставить неверный адрес. Это не основание запретить сохранение всего документа.
- Переименование цели не переписывает пользовательский текст `[подпись]` автоматически.

Пользовательские внешние HTTP(S)-ссылки могут оставаться обычными ссылками. Они не являются межкурсовыми связями Synopsis. Для изображений по удалённым URL нужно отдельно решить загрузку в курс: предложение — локализовать при явном импорте, а при экспорте диагностировать внешние зависимости. Самодостаточность гарантируется только при включении байтов вложения в архив; молчаливо считать remote URL вложением нельзя.

## Факты

Факт хранится отдельной записью с содержимым Markdown, ID и единственным ownerNoteId. Ссылка на него в исходнике — источник истины для привязки к тексту.

После сохранения рассчитывается список Fact владельца, на которые больше нет ссылок: они доступны как комментарии без привязки. Этот индекс можно пересчитать; он не должен требовать постоянных координат DOM. Ссылка на чужой факт считается невалидной.

Стандартная Markdown-ссылка не позволяет вложить в неё другую ссылку. Поэтому нельзя без отдельного синтаксиса обещать несколько перекрывающихся фактов или одновременную обычную ссылку и факт на одном фрагменте. Поддерживаемые случаи фиксируются в S00 и отображаются пользователю честно.

## Выделение в чтении → локальная правка исходника

Предлагаемый алгоритм:

1. Рендерить Markdown с привязкой текстовых узлов к исходным диапазонам.
2. При выделении получить DOM Range и revision отображаемого конспекта.
3. Сопоставить границы исходнику с учётом escape-последовательностей, entities, Unicode и форматирования.
4. Проверить, что выбранный диапазон допускает корректную Markdown-ссылку.
5. Сформировать точечную правку, сохранив исходную разметку подписи там, где это корректно.
6. Проверить актуальную revision и существование цели, сохранить согласованную операцию.
7. Перерендерить чтение; рёбра карты не меняются.

AST-позиции помогают, но не решают автоматически сопоставление каждого символа DOM исходнику. Формулы, изображения и code blocks требуют отдельных правил. Поиск `indexOf(selection.toString())` не является корректной реализацией: он ошибается на повторяющихся фразах.

В S00 обязательна таблица поддержанных выделений: простой текст; кириллица и emoji; повторяющаяся фраза; часть слова; emphasis/strong целиком и частично; текст со скобками и экранированием; списки; ячейка таблицы; существующая ссылка; граница абзаца; соседство формулы; выделение внутри формулы; inline/fenced code. Для неподдержанных случаев необходимо понятное сообщение и отсутствие изменений, а не повреждение текста.

Произвольное ограничение только простым текстом нельзя молча объявить полной реализацией: ограничение записывается в D-03 и демонстрируется перед приёмкой S00.

## Минимальный набор регрессионных проверок

- `[старое имя](synopsis://note/id)` работает после переименования и снятия карточки.
- После удаления Note исходник не переписан, ссылка отображается невалидной.
- Из двух одинаковых фраз обёрнута именно выбранная.
- Текст до и после заменённого диапазона совпадает с исходником.
- Новая ссылка не создаёт ребро карты.
- Удаление маркера факта не удаляет текст факта.
- Старое выделение не перезаписывает более новую revision.
- Markdown → чтение → редактирование без изменения текста возвращает тот же исходник.
