# Проект формата .synopsis

Статус: техническое предложение v1. Пользователь утвердил один самодостаточный файл курса; ZIP, названия полей и файлов выбираются командой на S00/S01.

## Предлагаемая структура

`.synopsis` — ZIP-контейнер, содержащий:

```text
manifest.json
course.json
notes/<note-id>.md
facts/<fact-id>.md
assets/<asset-id>.<extension>
```

`manifest.json`: идентификатор формата `synopsis`, целочисленная schemaVersion, идентификатор курса, версия приложения-экспортёра, перечень файлов с размерами и контрольными суммами. Даты — метаданные, а не идентичность объектов.

`course.json`: заголовок курса; записи Note без дублирования markdown; Fact с ownerNoteId; Source/Asset; Card/LectureBox/CourseRoot; Edge с геометрией и подписями; прикрепления источников; настройки стилей и видимости. Пути к markdown и asset должны быть относительными внутри архива.

Пустые конспекты, конспекты без карточек и факты без привязки также включаются. Предлагается не включать временные кэши, HTML рендера и историю открытых вкладок: их отсутствие не теряет базу знаний. Перенос черновиков — отдельное решение D-05.

## Экспорт

1. Определить согласованную сохранённую revision курса. При открытых несохранённых редакторах показать, что будет экспортировано; не подменять явное сохранение.
2. Получить снимок метаданных, Markdown, фактов, геометрии и настроек.
3. Собрать реальные байты всех локальных PDF и изображений, включая данные, на которые ссылаются конспекты без карточек.
4. Проверить доступность файлов и внутренние отношения. Невалидные текстовые ссылки после удаления Note допустимы и переносятся как текст; отсутствующие обязательные файлы не должны игнорироваться. Проверить также изображения по удалённым URL и внешним локальным путям: для самодостаточного экспорта их байты должны быть включены в курс. Если получить их не удалось, показать незавершённую переносимость и не выдавать экспорт за полностью самодостаточный. Строгий отказ или отдельный явно обозначенный неполный экспорт определяется в D-13; тихий пропуск запрещён.
5. Создать архив. При ошибке не выдавать частичный файл за успешный экспорт.

Абсолютные пути, URL временного сервера, blob URL текущей вкладки и идентификаторы внешнего облачного хранилища не могут быть единственными адресами необходимых данных.

## Импорт

1. Прочитать manifest и проверить поддерживаемую версию до публикации курса в списке.
2. Проверить имена ZIP-записей, отсутствие выхода за целевой каталог, дубликатов путей, чрезмерного объёма распаковки и отсутствующих файлов. Значения лимитов установить на S01 и сделать сообщения понятными.
3. Проверить схемы записей, уникальность ID внутри курса и согласованность ссылок.
4. Разместить файлы и данные в изолированной промежуточной области.
5. Применить определённую политику конфликта импорта (D-04), затем атомарно опубликовать курс.
6. При ошибке сохранить прежние курсы; временные данные убрать только из точно выделенного каталога импорта.

Содержимое Markdown не исполняется как скрипт. Импортированный архив не получает права читать произвольные файлы компьютера по указанным в нём путям.

## Классы диагностики

| Ситуация | Предлагаемое поведение |
| --- | --- |
| Неподдерживаемая schemaVersion | Отказ с указанием версии; миграция только при наличии проверенного преобразователя |
| Повреждение ZIP, обязательного JSON/Markdown/вложения | Отказ без частичного изменения существующей базы |
| Markdown с адресом удалённого Note | Импорт допускается; текстовая ссылка невалидна и диагностируется |
| Ребро с отсутствующим концом / несовместимыми типами | Не отображать как валидное; явный отчёт и согласованная политика восстановления, не молчаливая потеря |
| Карточка без Note или факт без владельца | Ошибка структуры; требуется явно обозначенный режим восстановления либо отказ |
| Некорректная ссылка на страницу PDF | Оставить текст, сообщить проблему страницы; не подменять источник |
| Повторный импорт того же курса | Решение D-04; запрещено незаметно перезаписывать текущий курс |

В первом выпуске допустим строгий отказ для структурных ошибок, кроме невалидных текстовых ссылок, которые являются нормальным следствием удаления. Режим ремонта архива не входит автоматически в объём работ.

## Изоляция и совпадающие ID

Хранилище адресует сущность в контексте курса, например парой `(courseId, noteId)`. При импорте как копии можно выдать новый courseId и сохранить внутренние noteId, если все запросы действительно ограничены курсом. Альтернатива — полное переназначение ID с переписыванием всех ссылок и отношений; её нельзя выполнять частично. Окончательная стратегия фиксируется на S01.

## Обязательная проверка переносимости

Экспортировать контрольный курс с двумя лекциями, обычными и внешними понятиями, примером, задачей, фактами, конспектом без карточки, PDF, изображением и изогнутой межлекционной линией. Импортировать в чистое хранилище, не имеющее доступа к исходным путям. Проверить чтение, редактирование, открытие источника, геометрию и настройки. Побайтное равенство ZIP не требуется; содержимое Markdown/вложений и смысл данных должны совпадать.
