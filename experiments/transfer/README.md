# S00-C: перенос и архив

Это автономный spike, а не production-модуль и не окончательный контракт S01.
Он использует только Python standard library (`zipfile`, `json`, `hashlib`).

Запуск из корня репозитория:

```powershell
python experiments/transfer/transfer_spike.py
```

Точный успешный результат:

```text
PASS: ZIP import/export; PDF/image bytes; card/note deletion; malformed rejection
EXPECTED ERROR: invalid ZIP (existing storage unchanged)
```

Проверка создаёт уникальный `transfer-spike-work-<uuid>` внутри этого каталога и удаляет его после
завершения (при сбое очистки печатает предупреждение). Fixture содержит настоящие байты PDF и PNG; оба включаются в ZIP и
после импорта в отдельное чистое хранилище сравниваются побайтно. В снимке есть
`Note` без `Card`, `Fact`, настройки карты, PDF и изображение.

Покрытые классы отказа: не-ZIP (`invalid ZIP`), небезопасное/дублируемое имя
записи (`unsafe ZIP entries`), неверный manifest, неподдерживаемый manifest,
несовпадение набора/контрольной суммы файла и неверная структура курса. Импорт
полностью валидирует архив до публикации; при ошибке исходное хранилище не
изменяется. В test-run доказан `invalid ZIP`.

Ограничения spike: лимиты размера распаковки, миграции schema, политика
конфликтов повторного импорта и UX-диагностика остаются для S01/S06. Markdown
с удалённой целью сохраняется как текст и не блокирует загрузку.
