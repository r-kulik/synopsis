# Работа через Synopsis MCP

Сервер называется `synopsis`; клиент может показывать инструменты с префиксом.
Ищи по именам инструментов и их описаниям. Схемы аргументов получай из tools,
а не из догадок. Все ID и внутренние URL возвращает сервер.

## Порядок действий

1. `list_courses` / `get_course` — проверить, не существует ли уже черновик
   текущей задачи. Новый запрос не означает продолжение чужого курса.
2. `create_course(title)` — новый курс; сохрани `course_id` в `progress.md`.
3. `register_presentation(course_id, filename, slide_count, title)` — каждый
   прочитанный файл. Используй устойчивые различимые имена (например,
   относительные пути при одинаковых именах файлов). Это запись inventory,
   не чтение файла; число слайдов проверяет агент по оригиналу.
4. `create_lecture` — сначала рамки и конспекты лекций. Для ссылок между ещё
   не созданными сущностями создай короткие содержательные заготовки с
   цитатами, затем дополни их через `update_note`. Не придумывай будущие UUID.
5. `add_concept`, `add_example`, `add_task` — сущности с `lecture_id` нужной
   рамки. `add_concept(external=true)` только для предпосылок вне курса.
6. `connect` — смысловые рёбра по note ID (не card ID). `label` — короткая
   причина/направление. Повтор пары ID и типа не создаёт дубликат ребра.
7. `add_fact` — комментарий с `owner_note_id`; сервер сам вставляет ссылку
   в тело владельца и повышает его revision. Перечитай владельца перед правкой.
8. `attach_file` — PDF или иллюстрация в разрешённом каталоге. Для PDF можно
   передать `lecture_id`, чтобы прикрепить источник к лекции. Источник/asset
   получает собственный URL. Для изображения вставь `![подпись](URL)` в текст.
9. `get_note` → `update_note` — передавай текущий `expected_revision` и
   отредактированный `body`. `markdown` из ответа содержит также автоматически
   добавленные ссылки на слайды; их не нужно дублировать в аргументе.
10. `validate_course` → содержательная проверка → `export_course`.

`create_lecture` / `add_*` принимают title, markdown, summary и `citations`:

```json
[
  {"presentation_id": "ID_FROM_REGISTER_PRESENTATION", "start_slide": 3, "end_slide": 7},
  {"presentation_id": "ANOTHER_REGISTERED_ID", "start_slide": 2}
]
```

Это пример формы, не действительные ID. Диапазоны включительны, с единицы.
Сервер отвергает пустые citations, неизвестную презентацию и номера за пределами
зарегистрированного числа слайдов. У обновления citations можно не передавать —
сохранятся прежние. Для новых разделов конспекта обнови ссылки на источники.

`get_note` возвращает `url`: его можно вставить как `[название](URL)` в другой
конспект. PDF-страница: `URL_ИСТОЧНИКА?page=2`. Проверяется реальное число страниц
PDF; соответствие «слайд → PDF-страница» всё равно проверяет агент.

## Ошибки и продолжение

- `isError` не означает успех. Исправь аргументы и проверь состояние.
- Ошибка типа ребра: не подменяй тип сущности ради ребра; выбери семантически
  допустимую связь или оставь Markdown-ссылку.
- Неизвестный ID / повтор заголовка: вызови `get_course`, найди канонический
  конспект. Настоящие омонимы различай уточняющими заголовками.
- Stale revision: перечитай `get_note`, объедини изменения, повтори с новой
  revision. Не затирай появившиеся комментарии.
- После таймаута создания проверь `get_course` до повторного вызова. Создание
  курса не идемпотентно; перезапуск процесса сохраняет черновики.
- Недоступный файл: по умолчанию читается только `WORKSPACE/inputs`; абсолютный
  путь допускается лишь внутри каталога, явно разрешённого оператором через
  `--input-root`. Не расширяй доступ на весь диск ради одного файла.
- Неподключённый сервер: останови сборку на плане и попроси подключение;
  не записывай архив вручную «временно».

## Что гарантирует сервер

ID создаёт код. Перед сохранением проверяются структура штатным импортёром,
типизированные отношения, внутренние ссылки и владельцы фактов. Перед
экспортом выполняется ещё и реальный импорт в новую временную библиотеку.
Черновая библиотека изолирована от основной, один MCP-процесс владеет каталогом
через OS-lock, команды сериализованы. Исправление JSON вручную не поддерживается.

`coverage_warnings` показывает нецитированные слайды. Это не доказательство
полноты: ссылка на диапазон 1–100 не доказывает, что агент прочитал 100 слайдов.
Титульные/служебные слайды можно осмысленно исключить, объяснив это в отчёте.

Текущие ограничения: максимум 1000 ZIP-записей (включая manifest), 32 MiB
на файл, 256 MiB суммарно до сжатия; до 10000 слайдов в записи inventory.
Не меняй лимиты автоматически: предложи тематическое разделение курса либо
согласованное уменьшение вложений. Полной проверки содержания, формул и качества
раскладки MCP не делает. PDF-конвертация и OCR в сервер не входят.

Рабочие черновики/exports сохраняются между запусками. `export_course` возвращает
абсолютный путь к новому архиву; повторный экспорт той же revision не затирает
иной файл. В текущей версии нет удаления/смены типа конспекта и редактирования
факта отдельной командой: не обходи это прямой правкой хранилища, запроси
необходимое расширение инструментов или создай новый черновой курс.
